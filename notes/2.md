**2. Configure PfSense remote syslog**  
Status → System Logs → Settings → Remote Logging. Point it at `100.99.54.59:5514`, protocol UDP. Since PfSense itself is a Tailscale node (`100.111.91.40`), traffic leaves the VM via the overlay — no PfSense-side NAT/firewall rule needed for the outbound syslog unless PfSense's own ruleset blocks egress on the Tailscale interface.

**3. Logstash grok filter for `filterlog`**  
PfSense's default firewall log format is CSV-like (`filterlog`), not free text — plan a `csv` or `grok` filter that splits it into fields (action, interface, direction, protocol, src/dst IP, src/dst port). Decide now whether to map to ECS field names, since TheHive/Cortex ingestion later will be cleaner if the schema is consistent from the start.

**4. Kibana validation**  
New index pattern, confirm parsed fields, quick dashboard/panel as report evidence.

**5. Document the Tailscale pivot**  
This is a nice architectural beat for the report: _bridged (failed on WiFi) → NAT+port-forward (host-level workaround) → Tailscale overlay (per-VM identity, host-independent reachability)_. It also gives you a legitimate answer to "why not just fix bridging" if anyone in review asks.
